# Neural corrector — collect, train, evaluate, and export

> **Data update (7 November 2026):** the current collector records Neural-QR
> version 2 at G16/G32/G64/G128 with 4×4 pixels per cell. Use the
> [W-tube data guide](W_TUBE_DATA.md) to import current and eligible earlier
> recordings, generate clean targets and create harder paired synthetics.
> **W-tube and VW training, evaluation, export and browser integration are implemented**
> for this corpus. Follow the [demo guide](NEURAL_ZKBOO_DEMO.md) for device validation. The separate `multires` commands
> below still use prepared **2×2-cell datasets**.

The earlier **multires** training path consumes header-free Neural-QR recordings
at G8/G16/G32/G64/G128/G256 with **2×2 pixels per cell**, sixteen colors, and
four palette phases. One checkpoint shares its convolution/attention trunk
across sizes and learns separate low-frequency cosine coefficients for each
grid. Its six alternating bottleneck blocks contain six convolutions and six
attention layers in total. Its input has eight
capture slots; every training example uses four to eight observations, with
one or two observations from each phase. Its output is a corrected logical
matrix of sixteen-class logits. See [architecture and masks](NEURAL_CORRECTOR.md).

The trained `U-tube-2x-attn` model and its existing 4×4-cell datasets remain a
separate experiment. Their commands are retained [below](#independent-u-tube-experiment-prepared-44-cell-datasets).
The new acquisition matrices carry raw symbols: multires **exact matrix** metrics
are not the earlier OBM5 CRC/RS recovery metrics, and are not an authentication
or goodput measurement.

## Train W-tube

Use the corpus generated by [the W-tube rebuild](W_TUBE_DATA.md), whose recording
roots default to `local-data/recordings`, `local-data/recordings-1` and
`local-data/recordings-0`. The rebuild prints stage/count progress and supports
large manifests without changing the dataset JSON contract. The model
profile is **`W-tube`**, with four pixels per cell and G16/G32/G64/G128. It has
487,760 parameters and two complete full-resolution U stages; see
[the architecture and diagrams](NEURAL_CORRECTOR.md#w-tube). Existing U-tube and
two-pixel multires checkpoints do not initialize this architecture.

Start a new run:

```sh
python experiments/neural-corrector/train.py \
  --model W-tube --frames 8 \
  --train local-data/w-tube/real/train local-data/w-tube/synthetic/train \
  --validation local-data/w-tube/real/validation \
  --paired-targets --real-fraction .5 \
  --origin-ratios native=.5,resampled=.35,header-g64=.15 \
  --batch-size 8 --accumulate 4 --lr .0001 --steps 32000 \
  --validation-samples 0 --device cuda \
  --out checkpoints/neural-corrector/w-tube-phase8
```

`--batch-size 8 --accumulate 4` means **32 sample bursts per optimizer update**,
all at one selected grid: 16 real and 16 paired synthetic examples. Grid sizes
are selected uniformly within the chosen recording origin; 32,000 is the total
number of optimizer updates, not the count per grid. Each real/synthetic pair
uses the same logical target and observation count. The 4:1 synthetic corpus
ratio supplies more corruption choices, while the training ratio stays 50/50.

Every sample draws K uniformly from four through eight distinct captures, with
one or two captures from each palette phase. Inputs contain eight RGB slots and
eight binary presence planes; unavailable RGB is gated in the model. Existing
phase permutations, within-pair order randomization, aligned horizontal/vertical
flips and mild real-only photometric augmentation remain enabled. Targets and
loss masks follow every geometric transformation. See
[input and loss masks](NEURAL_CORRECTOR.md#masks-and-the-training-objective).

G128 has 512×512 input crops and processes two full U stages. If its microbatch
does not fit your GPU, lower `--batch-size` and increase `--accumulate` to retain
32 samples per update, for example `--batch-size 4 --accumulate 8`. The parameter
count alone does not predict activation memory. Both training's random K4…K8
draws and the complete validation presets require at least two distinct captures
of every phase per target. The importer can retain smaller pools, but this
training recipe rejects them; do not duplicate captures to fill slots.

### Train VW

**`VW` adds a third complete U spatial path**, including its own target-sized
bottleneck, feature skips and residual fusion. Each stage keeps the current
W-tube bottleneck's two convolutions and two attention layers. The architecture
has **696,400 parameters**; see [the three-path diagram](NEURAL_CORRECTOR.md#vw).
This is a new profile, while `W-tube` continues to select the two-stage model.

Reuse the existing version-2 `local-data/w-tube` corpus. The model change requires
no new recordings, dataset regeneration or file conversion. Start this experiment
from scratch, without `--initialize`:

```sh
python experiments/neural-corrector/train.py \
  --model VW --frames 8 \
  --train local-data/w-tube/real/train local-data/w-tube/synthetic/train \
  --validation local-data/w-tube/real/validation \
  --paired-targets --real-fraction .5 \
  --origin-ratios native=.60,resampled=.25,header-g64=.15 \
  --loss rs-weighted-ce --rs-loss-mix .25 --rs-parity 32 \
  --batch-size 8 --accumulate 4 --lr .0001 --steps 32000 \
  --validation-samples 0 --device cuda \
  --out checkpoints/neural-corrector/vw-phase8
```

This retains 32 bursts per update, the 50/50 paired real/synthetic mixture,
K4–K8 phase grouping, all current augmentations and the
[RS-aware objective](#rs-aware-weighted-cross-entropy). The origin mix matches
the latest W-tube refinement: 60% native, 25% resampled and 15% header-G64 among
real examples. These are explicit experiment settings; the shared origin-ratio
defaults remain 50/35/15. Full-resolution activations pass through a third U,
so if G128 exceeds available VRAM, use `--batch-size 4 --accumulate 8` to retain
the same effective batch size.

Evaluate its selected checkpoint on the same complete validation corpus:

```sh
python experiments/neural-corrector/evaluate.py \
  --dataset local-data/w-tube/real/validation --split validation \
  --checkpoint checkpoints/neural-corrector/vw-phase8/best.pt \
  --max-samples 0 --rs-parity 32 --device cuda \
  --out local-results/neural-corrector/vw-phase8-validation.json
```

Compare sustained G128 RS+CRC replay recovery and CER with the W-tube baseline,
while checking that G64 recovery remains strong. Replay is still a diagnostic
benchmark, not live packet authentication. Checkpoint selection remains balanced
raw exact-matrix recovery with CE as its tie-breaker; it does not switch to RS
replay for this profile.

To continue a VW run later, keep `--model VW`, add
`--initialize checkpoints/neural-corrector/vw-phase8/best.pt`, select a new empty
output directory and set the intended refinement learning rate. Initialization
loads weights and provenance with a fresh optimizer; it is not an exact optimizer
resume. Both profile and three-stage geometry are checked. A two-stage W-tube
checkpoint cannot initialize VW through an automatic conversion. VW and W-tube support static ONNX export and the current Neural-QR demo.

### W-tube sampling policy

Quotas apply to the **whole optimizer update**, before splitting it into
microbatches. Changing `8 × 4` to `4 × 8` therefore preserves the sampling policy.
The default hierarchy for both `W-tube` and `VW` is:

1. Draw one recording origin for the optimizer update using
   `--origin-ratios native=.5,resampled=.35,header-g64=.15`.
2. Choose a represented grid uniformly within that origin.
3. In paired mode, allocate half the update to real examples and half to their
   synthetic counterparts. Every example in the update has the same origin and
   geometry, even when it is split into microbatches.
4. Balance real examples across the available acquisition directions, then draw
   physical sessions, targets, phases and capture bursts within that population.

Each synthetic counterpart matches its real example's origin, logical target
and observation count. The larger synthetic corpus supplies more corruption
choices without changing the overall 50/50 real/synthetic mixture. Origin ratios
are expected **global proportions across updates**, not three proportions applied
separately inside every grid. They must be finite, nonnegative and sum to one;
requesting a positive share for an unavailable origin fails with an actionable
error. Set an absent origin to zero rather than silently changing the requested mix.

With all four grids available for native and resampled evidence, and header data
only at G64, the default gives:

| Population | Expected share |
| --- | ---: |
| Native real examples | 50% of real examples |
| Resampled real examples | 35% of real examples |
| Header-G64 real examples | 15% of real examples |
| G16 / G32 / G128 optimizer updates | 21.25% each |
| G64 optimizer updates | 36.25% |

An effective batch of 32 has 16 real and 16 paired synthetic inputs from the
selected origin. Origins vary across optimizer updates. To emphasize newly
collected native sessions, use
`--origin-ratios native=.55,resampled=.30,header-g64=.15`; this preserves the
same expected grid distribution when coverage is complete. Direction coverage
is reported explicitly: an origin cannot supply a direction it does not contain.
Expected origin/grid coverage is recorded in `settings.json` and actual origin
counts appear in training reports.

The existing explicit `--native-real-fraction` remains an alternative policy:
uniform grids, then a native quota within each grid/direction, then equal shares
among its available auxiliary origins. It is mutually exclusive with
`--origin-ratios` and does **not** set global origin percentages. Other model
profiles keep their existing source/direction policy. Session/split boundaries,
K4–K8 draws, phase permutations, aligned flips and real-only photometric
augmentation are unchanged.

### W-tube validation and continuation

Validation uses fixed seeded phase-paired groups and nested K4/K5/K6/K7/K8
subsets, not consecutive-frame windows. When native real validation candidates
exist, the headline metrics and checkpoint-selection score use **native real
captures**. Auxiliary origins are reported separately. If native validation is
absent, the report explicitly labels its result **auxiliary-only**; that result
does not demonstrate recognition of the new native captures. The selection score
continues to balance grid size, acquisition direction and observation count
within the selected population. Exactness means all logical **data cells** are
correct; it does not imply packet CRC/ECC recovery or authentication success.

The saved report records the selected population and its grid coverage separately
from all evaluated grids. Origin is a dimension in the canonical metric table,
so auxiliary results remain available without repeating nested aggregate trees.
If native captures cover only some grids, auxiliary captures do not silently
fill the missing grids in the primary score; check coverage when comparing runs.
See [metrics and report files](#metrics-and-report-files) for the current schema.

Evaluate the selected checkpoint on the full validation corpus:

```sh
python experiments/neural-corrector/evaluate.py \
  --dataset local-data/w-tube/real/validation --split validation \
  --checkpoint checkpoints/neural-corrector/w-tube-phase8/best.pt \
  --max-samples 0 --device cuda \
  --out local-results/neural-corrector/w-tube-phase8-validation.json
```

#### Reed–Solomon and CRC validation benchmark

Raw exact-matrix accuracy remains the checkpoint-selection metric. The recording
files contain random logical symbols, not encoded RS packets, so an actual RS
decoder cannot repair their raw predictions directly. Validation now adds a
separate **recorded-error replay** benchmark, enabled by default with
`--rs-parity 32` in both training and evaluation. Use `--rs-parity 0` to disable
it, or an even parity count from 2 to 64 to measure another redundancy budget.
Node.js runs the repository's existing RS implementation; there is no second
Python RS implementation or additional package dependency.

For each inference result:

1. Select data cells only, in row-major order; pack two 16-color symbols per
   byte, high nibble first. An odd trailing cell is excluded from the byte
   benchmark but remains included in raw matrix accuracy.
2. Compare predicted and expected bytes to obtain the observed XOR error
   pattern. This happens **after classification** and never changes its output.
3. Build a diagnostic payload, append a four-byte CRC-32, and encode balanced
   shortened RS blocks of at most 255 bytes. Interleave the blocks round-robin
   within exactly the available byte capacity. Parity and CRC consume capacity;
   they are not appended as free, perfectly received evidence.
4. Apply the measured XOR pattern to the entire encoded packet, including its
   parity and CRC positions. Run a blind RS decoder and then CRC verification.
   Neither decoder receives expected symbols, error locations or clean payload.
5. Only after acceptance, compare the recovered payload with the diagnostic
   payload and count exact recovery or wrong acceptance.

The console separates RS decoding, CRC acceptance and verified replay recovery.
Per-grid summaries and the compact grid/direction/origin/K table retain those
counters and the payload/wire-byte budget; per-session and per-capture logs are
not added. Too-small matrices are explicitly ineligible for the chosen parity
budget. Replay never replaces raw exactness, changes model weights, or selects
a checkpoint. CRC detects accidental corruption; it is not authentication.

The benchmark assumes the recorded error pattern would transfer to a different
symbol arrangement carrying the encoded packet. Content-dependent optical
errors can violate that assumption. Consequently, **RS+CRC replay is not measured
live packet recovery**. It is useful for choosing redundancy and comparing
models on the same recorded evidence before recording encoded-packet tests.

For example, a G64 matrix with 3,136 data cells offers 1,568 wire bytes. With
32 parity bytes in each of seven blocks and four CRC bytes, the diagnostic
payload is **1,340 bytes**. Reports record the actual capacity for every grid.

Neural-QR version-2 synthetics automatically use the camera model described in
[the data guide](W_TUBE_DATA.md#camera-scaled-coherent-corruptions), including
when `synthetic.py` is called with the `standard` recipe. The recipe changes
corruption strengths; it does not select the sampling geometry.

W-tube weights into a **new, empty run directory**. Stop the current training

### RS-aware weighted cross-entropy

Ordinary masked CE remains the default (`--loss ce`). For sixteen-color Neural-QR
datasets, `--loss rs-weighted-ce` adds a bounded emphasis on RS blocks near their
correction budget. It uses the same `--rs-parity` as validation replay; weighted
training requires a nonzero even value from 2 through 64. This option changes
training only: there is no change to the model, recordings, dataset files,
inference, or checkpoint weight shapes.

The loss uses the canonical data-cell mask, row-major order and high-nibble-first
packing described above. Two cells form one byte. If either or both cells are
wrong, that byte counts as **one** error. Bytes are assigned to the same balanced
shortened blocks and round-robin interleave as validation replay. Reference cells
are excluded; an odd trailing data cell remains in CE with weight one. Samples
whose capacity cannot hold the chosen RS+CRC layout use ordinary CE.

With `--rs-parity 32`, each block's guaranteed unknown-error budget is 16 bytes.
The loss counts hard prediction errors with gradients detached and assigns:

| Wrong bytes in an RS block | Weight for its data cells |
| --- | ---: |
| 0–12 | 1 |
| 13–24 | 3 |
| 25 or more | 2 |

For another parity count, let `t = parity / 2`; the two boundaries are
`floor(.75*t)` and `floor(1.5*t)`. These are experimental emphasis bands around
the budget, not alternate RS correction limits. Blocks just beyond the budget
can be more useful to improve than blocks already well below it; severely
corrupted blocks still contribute, with a bounded weight.

For each example, compute ordinary masked CE and a second CE normalized by the
sum of its cell weights. `--rs-loss-mix .25` gives:

\[
L = 0.75\,L_{\mathrm{CE}} + 0.25\,L_{\mathrm{weighted\ CE}}.
\]

Both terms first normalize within each example, then average examples equally
across the microbatch. Larger grids or higher total block weights do not gain
extra example weight. Setting the mix to zero recovers ordinary CE. Uniform
weights within an example also cancel under normalization: a one-block example
with no unpaired trailing cell retains ordinary CE. The weighting redistributes
emphasis within a matrix, rather than upweighting entire matrices. No gradient passes through error counts
or weight selection; gradients flow through the weighted CE values.

**Keep the augmentations enabled.** Each phase-grouped training sample retains
two booleans identifying its horizontal and vertical flips. Before assigning RS
blocks, the objective reverses these flips on the small G×G CE, hard-error and
mask maps. The camera inputs remain augmented, and gradients through the flipped
CE map still reach the corresponding logits. No full-size RGB copy or per-cell
identifier tensor is needed. Phase permutations consistently relabel targets by
XOR and reorder input slots; they leave spatial membership and the correct/wrong
status of each cell unchanged under the corresponding label permutation.
Photometric noise, tint and exposure augmentation need no special handling.

The raw matrices are not RS codewords, so this objective does not enforce an RS
syndrome or run a differentiable decoder. Its block weights are a heuristic for
the proposed packet layout. Unchanged validation CE, exact matrices and RS+CRC
replay establish whether it helps. Raw CE/CER remain separately reported from
the optimized objective, and checkpoint selection remains the balanced raw exact
score with CE as its tie-breaker.

### EMA feature self-distillation

For an already trained **W-tube or VW**, enable `--self-distillation` to train
the first U's features against the final U's features from a frozen EMA teacher.
A residual projector with two 3×3 convolutions, nonlinearities and a skip
connection adapts the student's features. The
[architecture diagram and mask definition](NEURAL_CORRECTOR.md#training-only-ema-feature-distillation)
describe the two paths. The ordinary supervised objective remains active on all
student examples, including when `--loss rs-weighted-ce` is selected.

| Option | Default | Meaning |
| --- | ---: | --- |
| `--self-distillation` | Off | Enable the auxiliary objective for W-tube/VW. |
| `--distill-weight` | `.05` | Maximum multiplier of normalized feature distance. |
| `--distill-ramp` | `1000` | Optimizer updates to reach the maximum multiplier. |
| `--ema-decay` | `.995` | Teacher parameter EMA decay, applied once per optimizer update. |
| `--distill-noise-std` | `.01` | Additional student noise standard deviation in RGB [0,1] units. |
| `--distill-tint-stops` | `.04` | Additional student per-channel gain range in stops. |
| `--distill-exposure-stops` | `.04` | Additional student exposure range in stops. |

Both branches share the sampled burst, missing slots, phase permutation, H/V
flips and existing real-only photometric augmentation. The student then receives
the extra perturbations above; the teacher does not. The extra tint/exposure
gain is shared across each burst, while pixel noise differs across captures.
Synthetic examples also receive this extra student augmentation. Neither path
changes the sender labels, data mask or stored recordings. The teacher's
physically captured inputs are still imperfect; this is a consistency objective,
not clean-target image supervision.

**Continue the trained model rather than starting from scratch.** The following
bounded refinement retains the latest 60/25/15 origin mix and effective batch
of 32. Use the existing synthetic dataset to start immediately:

```sh
python experiments/neural-corrector/train.py \
  --model VW --frames 8 \
  --train local-data/w-tube/real/train local-data/w-tube/synthetic/train \
  --validation local-data/w-tube/real/validation \
  --paired-targets --real-fraction .5 \
  --origin-ratios native=.60,resampled=.25,header-g64=.15 \
  --initialize checkpoints/neural-corrector/vw-phase8/best.pt \
  --loss rs-weighted-ce --rs-loss-mix .25 --rs-parity 32 \
  --self-distillation --distill-weight .05 --distill-ramp 1000 --ema-decay .995 \
  --batch-size 4 --accumulate 8 --lr .00002 --steps 8000 \
  --validation-samples 0 --device cuda \
  --out checkpoints/neural-corrector/vw-distill
```

For W-tube, use `--model W-tube`, its own checkpoint and a distinct output
directory. A W-tube checkpoint cannot initialize VW. The student weights are
loaded normally; the teacher is copied from them before training. The optimizer,
residual projector and weight ramp start fresh. Gradient accumulation does not
multiply the EMA update frequency or shorten the ramp.

To use the enhanced glare/shade distribution, regenerate only the synthetic
training branch from the existing managed build's clean targets and real
captures. This preserves recorded data and pairing identities:

```sh
python experiments/neural-corrector/synthetic.py \

  --paired-real local-data/w-tube/real/train \
  --recipe w-tube --synthetic-ratio 4 --frames 8 \
  --severity-min .5 --severity 1 --seed 42 \
  --out local-data/w-tube/synthetic-glare/train
```

Use a new or empty output directory; add `--plan` first for an estimate if needed.
Then replace only the second `--train` path above with
`local-data/w-tube/synthetic-glare/train`. There is no need to regenerate the
real validation set or change checkpoint metadata. The upgraded `w-tube` recipe
already enables structured light effects; its
[glare/shade controls](W_TUBE_DATA.md#screen-glare-shades-and-reflections) retain
easier examples alongside harder ones. If clean targets were prepared separately,
substitute their existing directory for `local-data/w-tube/clean/train`.

Only the student is validated and saved. Raw CE/CER still describe its
supervised predictions; the optimized objective and feature term are reported
separately as aggregate scalars. No feature arrays or extra per-burst logs are
written. The saved `best.pt` remains a normal same-profile corrector checkpoint;
teacher and projector weights are discarded, so restarting from it starts a new
distillation experiment rather than restoring the exact EMA trajectory.

```sh

  --dataset local-data/w-tube/real/validation --split validation \

```

phone→PC separately, and confirm G64 recovery is retained. Checkpoint selection
remains balanced raw exact recovery with CE as its tie-breaker. Training has an
extra teacher forward pass and feature loss; reduce microbatch size and increase
accumulation if needed. Student inference cost is unchanged. The [export workflow](CORRECTOR_LAB.md) deploys the resulting W-tube/VW student
without any training-only distillation layers.

## Train multires

Start the low-frequency, six-block model in a new run directory. Reuse the
existing `local-data/multires` datasets; this architecture update does not require
regenerating recordings or synthetics:

```sh
python experiments/neural-corrector/train.py \
  --model multires --frames 8 \
  --train local-data/multires/real/train local-data/multires/synthetic/train \
  --validation local-data/multires/real/validation \
  --paired-targets --real-fraction .5 \
  --batch-size 8 --accumulate 4 --lr .0001 --steps 32000 \
  --validation-samples 0 --device cuda \
  --out checkpoints/neural-corrector/multires-frequency6
```

Parent directories are scanned recursively for manifests. Each optimizer update
uses one grid size selected uniformly among available training sizes, with
homogeneous-size microbatches. Within that grid, source/group/session/target
sampling prevents a recording with more captures from dominating. Paired mode
uses equal numbers of real and synthetic examples of the **same logical target**
and the same K observation budget. Dataset counts do not determine this ratio:
`--real-fraction .5` keeps training **50/50**. Loss first averages over data cells
within each example and then over examples, so a larger matrix does not receive
a larger gradient simply because it has more cells.

`--batch-size 8 --accumulate 4` gives **32 sample bursts per optimizer update**:
16 real and 16 synthetic, all at one selected grid. The six-block bottleneck uses
more activation memory than the preceding run. If G256 exceeds available VRAM,
use `--batch-size 4 --accumulate 8` or `--batch-size 2 --accumulate 16` to retain
32 samples per update while reducing the microbatch. The samples per phase in
a stored burst can exceed eight; the model randomly draws only the four to eight captures
needed by that example. Sampling is not restricted to consecutive frames.
Training retains spatial flips, phase-pair permutations and small real-only
photometric augmentation with aligned targets/masks.

The command defaults to 32,000 total optimizer updates even if `--steps` is
omitted. With all six sizes, each receives about one sixth of those updates;
this is not 32,000 updates per size. All updates train the shared trunk. The live
bar shows training metrics only; validation prints at checkpoint intervals.
Each grid row has a stable order: **train real → train synthetic → val real**,
with CE/CER for each and exact matrices for validation. Unavailable sources
appear as `n/a`. This prevents a 50/50 mixed training number from being mistaken
for a directly comparable real-only validation number.

`CER (cell)` divides total wrong data cells by total data cells, giving large
matrices more weight. `CER(size)` averages the per-grid CER values equally over
represented sizes. Training CE averages examples, and exact-matrix checkpoint
selection still balances size, real acquisition group and K before using CE as
a tiebreak. The added metrics do not alter optimization or selection. Compare
real training and validation within the same grid; training numbers include
augmentation and average an interval of updates, whereas validation uses the
current checkpoint on unchanged held-out captures.

Saved metric tables retain grid, source, group and observation-count dimensions
from which these summaries are derived. The same measurements are stored once,
not repeatedly under `bySize`, `byFrameCount` and group/source trees. Per-session
and per-burst records remain opt-in. Inspect per-size values so success at G8
does not conceal failure at G256.

To continue a checkpoint trained with this current low-frequency/six-block

Initialization loads weights with a fresh optimizer; it is not an exact resume

recommended run. **A dense-anchor/four-block multires checkpoint from the

by `--initialize`; it is not silently converted or partially loaded. Keep that
run with its source revision. New checkpoints record the anchor representation,
six-block layout and grid sizes actually optimized; exporting an untrained size

The following controls describe the separate **standard OBM/U-tube recipe**.
W-tube uses the camera-scale geometry described in
[the W-tube data guide](W_TUBE_DATA.md#camera-scaled-coherent-corruptions), while
retaining the same broad types of photometric effects.

The standard generator applies an RGB stripe carrier before blur/resampling, curved and
chirped channel-dependent moiré, bounded subcell jitter, short motion blur,
color/gamma changes, clipping, and shot/read noise. The following effects are
enabled by default:

| Option | Default | Effect |
| --- | --- | --- |
| `--white-balance-stops` | `.6` | Residual channel-dependent RGB gains in 80% of bursts. |
| `--exposure-stops` | `1.5` | Signed exposure gain in 80% of bursts, with highlight/shadow clipping. |
| `--shade-opacity` | `.45` | Maximum strength of soft, rotated rectangle/ellipse shadows and reflections. |
| `--shade-probability` | `.7` | Probability of a burst receiving one broad shape, sometimes with a smaller second shape. |
| `--glare-probability` | `.65` | Probability of a drifting elliptical highlight with a broader veiling halo. |
| `--glare-strength` | `.6` | Maximum glare strength before severity scaling; zero disables it. |
| `--capture-probability` | `.75` | Probability of a burst receiving the reduced-capture-resolution stage. |
| `--capture-min-scale` | `.25` | Minimum native capture side as a fraction of the stored crop side. |
| `--capture-max-scale` | `1` | Maximum native capture side as a fraction of the stored crop side. |
| `--capture-blur-sigma` | `.35` | Maximum Gaussian blur sigma in native capture pixels; selected bursts draw between half and all of this value. |
| `--severity-min` | omitted | If set, draw one severity per independent burst, uniformly from this minimum to `--severity`; otherwise use fixed severity. |
| `--rolling-shutter-stops` | `.65` | Maximum row-dependent exposure-band strength, with mild channel variation. |
| `--rolling-shutter-probability` | `.7` | Probability of correlated drifting rolling-shutter bands/skew. |
| `--rolling-shutter-skew` | `.5` | Maximum row-dependent horizontal displacement in dense-crop pixels, before severity scaling. |
| `--bursts-per-target` | `1` | Independently seeded corruption trajectories for each clean target. |
| `--motion-probability` | `.7` | Fraction of bursts with integrated exposure motion. |
| `--linear-blur-pixels` | `2.5` | Full arbitrary-direction exposure travel in dense-crop pixels, before severity scaling. |
| `--rotation-blur-degrees` | `.35` | Full rotational sweep around a varying center, before severity scaling. |
| `--zoom-blur-fraction` | `.006` | Full radial scale change during an exposure, before severity scaling. |
| `--motion-samples` | `7` | Temporal samples averaged per simulated exposure. |
| `--rgb-offset-probability` | `.6` | Probability of channel-offset exposure windows, conditional on motion being active. |
| `--rgb-offset-pixels` | `.5` | Maximum channel displacement along the exposure trajectory in dense-crop pixels, before severity scaling. |

Photometric and motion strengths are scaled by `--severity`; at `.65`, a `.65`-stop rolling-shutter
limit becomes `.4225` stops. Zero strength disables its effect; set rolling-shutter
probability to zero to disable both bands and skew, or shade probability to zero
to disable overlays. Capture resolution and its blur are separate geometric
controls, not severity-scaled. `--severity 0` returns the clean crop unchanged,
including bypassing the capture-resolution stage.

Rolling-shutter effects approximate exposure bands from a rolling readout and
screen flicker: broad/narrow bands evolve over successive frames, with slight
tilt and color variation. A small row-dependent skew is bounded together with
registration jitter to remain below half a four-pixel cell. Exposure blur can
spread neighboring-cell evidence while keeping the target grid centered.
This does not simulate a transition between different displayed payloads; those
mixed-label captures should still be excluded.

Shadows multiply the image by a spatially varying, slightly tinted attenuation;
reflections add light with highlight clipping. Shapes vary in angle, aspect,
position, edge softness and opacity gradient, with correlated movement across a
burst. The main shape's bounding rectangle covers roughly 18–32% of the crop;
ellipses and edge clipping reduce the affected area. Neither corruption choice
nor its parameters depend on payload symbols. Multiple independently seeded
bursts provide different conditions for the same target, while frames within a
burst remain correlated.

Glare adds a localized bright core and a wider, slightly tinted scattered-light
halo. The halo reduces local contrast; the core can saturate highlights. Its
position and intensity evolve smoothly through a burst. Glare has an independent
random stream, so changing its controls does not redraw unrelated nuisance
parameters. A severity range preserves moderate examples alongside hard ones;
the recipe records its bounds and each capture records its burst's actual value.

Reduced capture resolution approximates a small phone display occupying fewer
pixels in the PC camera, even though rectification produces a fixed-size crop.
After the other image effects and sensor noise, selected bursts use area
downsampling, a small Gaussian blur at that native resolution, and bilinear
upsampling to the original crop size. One native side and blur sigma are drawn
per burst and kept fixed across its exposures. The native side is uniform over
the integer pixel sizes in the configured scale range; an independent random
stream leaves existing artifact draws unchanged. The recipe and each burst's
capture settings are recorded in synthetic provenance.

At the default `.25–1` scale range, G64 crops go from 256×256 to 64–256 pixels
per side and back; G128 crops go from 512×512 to 128–512 and back. The lower
endpoint is one native pixel per matrix cell. That is an intentionally difficult
case, not a guarantee of recoverable symbols. Upsampling does not restore lost
spatial evidence. This stage preserves model input size, labels and recording
formats, and does not simulate marker/header detection or full camera geometry.
Set `--capture-probability 0` to disable the entire stage; setting only blur
sigma to zero still permits downsampling.

Motion blur now integrates several centered exposure samples with arbitrary-
direction linear travel, rotation around an off-center pivot and radial zoom.
Strength/direction evolve
coherently within a burst; zero controls disable the respective effects. This
models image evidence spread, not a changed class label or integer-cell shift.

RGB-offset blur shifts each channel's exposure window along the same linear,
rotational and radial trajectory. Centered channel offsets keep the mean window
aligned, and a dense-crop pixel bound limits the displacement. The sampled offsets
remain correlated within a burst; their independent random stream leaves other
artifact draws unchanged. This approximates motion-related color misregistration
and fringing, without assuming that every RGB camera exposes its channels at
different times. It acts only when motion is active; setting either new control
to zero disables it, and severity zero remains clean. Labels and masks do not move.

These are **calibrated-crop approximations**, not a full camera/display/readout
simulation. They do not reproduce detection, recalibration, or header failures.
The algorithm/settings and independent burst identity are recorded in synthetic
provenance. Synthetic classical baselines are recomputed from each corrupted
crop; real baselines use independently captured current-exposure samples.
Held-out real recovery must establish whether the additional effects help.

## Train and evaluate

The shared training path uses plain PyTorch/AdamW, float32 and ordinary masked
cross-entropy by default, with microbatches of 4 and accumulation of 4 (effective
batch 16). The optional [RS-aware objective](#rs-aware-weighted-cross-entropy)
applies to Neural-QR datasets; the prepared OBM experiment here retains plain CE.
Training defaults to **32,000 updates**, learning rate `1e-4` for fresh weights or
`5e-5` for an initialized checkpoint, and weight decay `.01`. Full validation
runs every 1,000 updates. `--steps`, `--lr`, `--eval-every` and
`--validation-samples` remain explicit controls. There is no adaptation recipe,
hard-cell objective or plateau scheduler.

Real training stacks receive mild online photometric augmentation, after random
stack assembly and before the model's existing [-1,1] input clip:

| Option | Default | Units and behavior |
| --- | ---: | --- |
| `--real-noise-std` | `.008` | Gaussian noise standard deviation in RGB [0,1] units, about two camera-byte levels; independent across exposures/pixels. |
| `--real-tint-stops` | `.06` | Small per-channel log2 gains, shared across a stack. |
| `--real-exposure-stops` | `.08` | Small global log2 gain, shared across a stack. |

Set all three to zero to disable this augmentation. Its dedicated random stream
does not change sampler draws. It does not modify synthetic inputs, stored real
captures, labels, masks, validation or inference. Calibration overshoot is retained
until the model's final input clip. Settings and provenance record the controls;
real training CE now measures augmented inputs, so an initial rise relative to an
unaugmented run is not by itself a regression. Compare unchanged validation.

For a fresh synthetic pilot:

```sh
python experiments/neural-corrector/train.py \
  --train local-data/synthetic-train \
  --validation local-data/synthetic-validation \
  --frames 5 --device cuda --out checkpoints/neural-corrector/tube-pilot
```

Microbatches share a grid size and palette. Reference cells and inactive palette
classes are excluded from the data-cell objective. Standard source sampling
remains available; `--paired-targets` enables the matched-real/synthetic route
[below](#training-another-run). An optional `--session-groups` sidecar
balances real acquisition directions and adds direction-specific evaluation.

For a quick CPU pipeline check, use `--device cpu --steps 10 --batch-size 1
--accumulate 1 --eval-every 5 --validation-samples 4` without paired sampling.
Paired sampling requires an even effective batch of at least two. Short smoke
runs validate wiring and need not recover payloads.

Exact recovery uses the current JS palette mapping, reliability ranking, RS and
CRC; accepted bytes are compared with expected bytes afterward. An accepted
incorrect payload stops training for investigation. Expected payload bytes never
enter model inference or repair.

The trainer evaluates at step zero. An initialized model is eligible for
`best.pt` immediately, preserving its starting performance if training never
improves it. A fresh model's random step-zero weights are diagnostic only.
With explicit real groups, fixed-frame checkpoint selection uses mean exact
recovery across those groups, then mean CE as the tie-break; otherwise it uses
global metrics. U-tube-2x-attn averages the per-count selection metrics across
K=4/5/6/7/8, balancing real groups within each K when the sidecar is supplied.
Read the per-direction results too: mean recovery alone can improve while a
still-failing direction stays at zero.

`--validation-samples 0` evaluates all validation captures and is the default.
Capped evaluation uses a fixed session/profile-balanced subset and must include
every mapped real group. Standalone `evaluate.py --max-samples 0` also evaluates
all examples. Default reports store CE/CER counters and exact-recovery counts
in canonical group/K rows, with a small aggregate headline. OBM reports also
retain aggregate CRC-recovery counters in that headline. Available p50/p95
inference timing is kept in standalone evaluation metadata. Confidence-
calibration measurements and per-session or per-burst/capture diagnostics
require the separate detailed output; they are not saved in the lean history.
See [report contents](#metrics-and-report-files).

Multiframe reports count complete input groups, not individual exposures.
The table's `inputCaptures` counts consumed observations. Unused captures and
incomplete-group diagnostics remain available in the detailed report's
`burstGrouping`; the default files retain only the capture method and seed.
Fixed-frame models make disjoint T-frame groups
within each phase pool. The phase-grouped model pairs observations within each
phase, combines four phase pairs of one logical matrix, and evaluates nested
K=4…8 subsets. Six complete logical groups with 32 captures per phase yield
96 candidates per K. Do not compare this denominator directly with a single-frame
report. Both classical and neural evaluation receive the same actual observations;
expected bytes are checked only after independent RS/CRC acceptance. Offline
recovery rates do not measure live throughput.

The evaluation draw is a fixed seed-7 permutation within each phase burst.
Fixed-frame profiles group at their fixed T; U-tube-2x-attn makes pairs in each
phase and combines four pairs from the same logical matrix. It evaluates nested
4/5/6/7/8 subsets, starting with one capture from every phase. It is independent of timestamps, directory paths
and input-file order. Existing checkpoints can be reevaluated without retraining;
use a new report filename because previous chronological reports used different
input groups. Standalone version-2 reports record the method and seed under
`metadata.capturePolicy`; training history records them once under
`validationMetadata.capturePolicy`. Checkpoint-selection weighting is separately
recorded in `selectionPolicy` within the same metadata objects. Detailed
subset-selection and burst-grouping diagnostics remain opt-in.

Whole-session and whole-payload split checks, including checkpoint ancestry,
remain mandatory. Keep sender/receiver identities intact when generating paired
targets. Use untouched test sessions only after selecting the model and receiver
settings on validation.

## Metrics and report files

The live tqdm bar contains only **training** statistics for the current interval:
overall CE/CER, real then synthetic CE/CER, mapped groups in sorted order, and
learning rate. Weighted-loss and self-distillation runs additionally show the optimized objective;
every CE field and table `lossSum` still describes unweighted masked CE, preserving
comparisons with ordinary-CE runs. W-tube also shows actual real-origin proportions in the stable
order native → resampled → header-G64. It does not repeat the last validation result. At each validation
step, a stable multiline summary prints:

- **Train:** consolidated interval metrics in the same order as the live bar.
- **Val:** CE/CER, raw exact count/rate, the separately labelled selection score,
  and K4→K8 recovery where applicable.
- **Val groups:** per-group CE/CER/recovery in sorted name order.

`--show-goal` optionally adds the phone→PC K4→K8/50% goal line at validation
steps. It is off by default. Training CER comes from the same masked forward
pass as training CE; it does not run CRC recovery on each training minibatch.
Both metrics exclude reference cells and inactive palette classes consistently
with the objective.

| File | Default contents |
| --- | --- |
| `settings.json` | Run configuration, model/input convention, augmentation and static sampling policy/coverage |
| `history.json` | Version-2 history: settings and column schemas once, then step metadata and canonical training/validation rows |
| `baseline-validation.json` | Lean step-zero evaluation document |
| `validation.json` | Lean evaluation of the selected checkpoint |
| `final-validation.json` | Lean final-step evaluation document |
| Standalone evaluation `--out` | The same lean evaluation document |
| `best.pt` | Selected weights and required training/split provenance |

The default files use canonical metric tables. Training rows distinguish grid,
source, acquisition group and recording origin. Evaluation rows additionally
distinguish K, the observation count. Rows store counts and metric numerators;
column names are declared once. Group, source, grid and K summaries can be
derived by grouping the rows. The files no longer repeat those same measurements
inside several nested aggregate trees.

`history.json` keeps static settings, sampling coverage and table schemas once.
Each validation-step entry contains the step, learning rate, elapsed time,
selection status, interval training rows, the training K histogram and validation
rows with a small headline/selection/coverage summary. The training origin counts
are actual draws; the configured fraction is a policy target whose attainable
value depends on coverage. There are no per-session, per-burst or per-capture
rows in the default files.

For weighted-loss runs, `settings.loss` is `rs-weighted-cross-entropy` and
`settings.rsLoss` records the static block-weighting policy. Each history step's
`training.meanObjective` records the optimized interval average separately from
the raw CE numerators in the training table. This adds one aggregate value per
validation step, without per-block or per-example logs.

Self-distillation adds its static policy in `settings.selfDistillation`. Each
history entry's `training` object records `meanSupervisedObjective`,
`meanDistillation` (raw normalized feature distance), `meanDistillationWeight`
(the mean ramp multiplier) and `meanWeightedDistillation` (the actual mean
weighted contribution). `meanObjective` is the combined optimized objective.
The live `SD` value shows raw feature distance followed by its actual weighted
contribution in parentheses. These are a handful of scalars per validation interval, with no
feature tensors, teacher predictions or per-capture records in the history.

Standalone files have `format: "neural-corrector-evaluation"` and `version: 2`.
Their static information is in `metadata`, column names in `tables.evaluation`,
and measurements in `rows`. A row can be read without relying on column order:

```python
import json

with open("local-results/neural-corrector/W-tube-validation.json") as stream:
    report = json.load(stream)
rows = [dict(zip(report["tables"]["evaluation"], row)) for row in report["rows"]]
```

Evaluation columns are `grid`, `source`, `group`, `origin`, `frames`, `samples`,
`lossSum`, `wrongCells`, `dataCells`, `exactMatrices`, `inputCaptures` and
`classicalExactMatrices`. Training uses the same dimensions except `frames`, and
omits both exact-recovery columns. `history.json` has
`format: "neural-corrector-training-run"`, `version: 2`, both column schemas in
`tables`, and step entries in `history`. Each step's `training.rows` and
`validation.rows` use those schemas; `training.frameCounts` is aligned with
`settings.frameCounts`.

For Neural-QR, `lossWeight: "samples"` means the table supports the following
reconstruction:

- Mean CE = sum of per-example CE numerators divided by the sample count.
- Cell error rate = wrong data cells divided by total data cells.
- Exact matrix rate = exact logical data matrices divided by the sample count.

The OBM experiment uses `lossWeight: "dataCells"`, so its mean CE is
`sum(lossSum) / sum(dataCells)`. Its exact counts describe recovered packets,
including classical recovery where available. Neural-QR exact counts instead
require every logical data cell to match; `classicalExactMatrices` is null.
Unavailable table dimensions are null rather than inventing a grid or origin
for older prepared OBM data.

The selection score still balances grid, acquisition group and K within the
selected real population; it must not be replaced with an unweighted sum of all
rows. Likewise, K4…K8 cases reuse nested captures and do not represent independent
recordings. Static grouping and coverage metadata retain those interpretations.

Checkpoint selection and console metrics use the full-precision measurements.
Only JSON serialization rounds finite floating-point values to eight significant
digits; integer counts stay exact. This reduces textual noise without changing
training or selecting a different checkpoint. Default JSON is compactly encoded;
its table schema remains explicit and can be pretty-printed after loading.

When diagnosing a specific failure, explicitly request a separate detailed
report. The normal output stays compact:

```sh
python experiments/neural-corrector/evaluate.py \
  --dataset local-data/real-validation --split validation \
  --checkpoint checkpoints/neural-corrector/U-tube-2x-attn/best.pt \
  --session-groups local-data/session-groups.json \
  --device cuda --max-samples 0 \
  --out local-results/neural-corrector/validation.json \
  --detailed-report local-results/neural-corrector/validation-details.json
```

The two output paths must differ. Detailed diagnostics can still be large and
are not embedded in training history. Existing reports are not rewritten.

reuse `target-clean-train`, or reconstruct it once with the first command below.
Generate the phase-grouped corpus into an empty `target-synthetic-train`
directory. This keeps seed 41 and the resolution/glare/RGB-offset recipe, while
correlating slow optical conditions across each four-phase group. Existing joined

```sh
# Reuse target-clean-train if already generated; otherwise run:
node scripts/corrector-dataset.mjs targets \

python experiments/neural-corrector/synthetic.py \

  --severity-min .45 --severity .9 \
  --glare-probability .7 --glare-strength .65 \
  --white-balance-stops .8 --exposure-stops 1.75 \
  --shade-opacity .55 --rolling-shutter-stops .8 \
  --capture-probability .75 --capture-min-scale .25 --capture-max-scale 1 \
  --capture-blur-sigma .35 \
  --rgb-offset-probability .6 --rgb-offset-pixels .5
```

`targets` reconstructs canonical clean matrices from the sender-derived bytes
and frame metadata already in the joined dataset. It verifies regenerated
headers, physical labels and masks against the source, and makes one clean
example per receiver session/payload/frame/phase, regardless of how many real
captures show it. **No noisy camera pixels are treated as clean truth.** The
sender/receiver identities, whole-payload identity and split are preserved;
recording files remain unchanged. Multiple joined source directories can be
passed as a comma-separated `--dataset` list. This command supports established OBM5
single logical frames with palette phases; it rejects incomplete multipart
payloads rather than inventing missing target bytes.

Thirty-two coherent phase groups with twelve captures per phase provide **384
synthetic observations per clean phase target**. A logical target has four such
phase targets. Slow optical conditions are shared across the four phases, while
noise, motion, moiré, rolling shutter and exposure drift change over the capture
timeline. `--phase-grouped` requires all four phases, G64/16 colors and consistent
logical data targets before writing outputs. This operates on established
prepared datasets and does not convert Neural-QR recordings.
Severity varies from .45 to .9 per burst. Glare, white balance, exposure, shade,
rolling shutter and resolution settings match the previous paired corpus; RGB
exposure offsets add the new effect. This retains moderate cases
rather than making every example maximally degraded. The resolution stage then
applies to 75% of bursts, independently of severity: G64 uses a native side of
64–256 pixels and blur sigma .175–.35 native pixels. Other bursts skip that stage.
The mixture includes full-resolution evidence; it does not assume that all
one-pixel-per-cell captures can be decoded. The generator reports the
actual target/sample count and estimated disk budget before writing; G64 RGB
tensors alone occupy 288 MiB per target at these settings. Channel offsets apply
to 60% of motion-active bursts, not 60% of all bursts, with a .5-pixel maximum
before severity scaling. The separate RNG keeps the other seeded draws intact.

Generate training targets **only from `real-train`**. Do not add validation or
test target matrices to training, including through a pilot checkpoint. Synthetic
derivatives of a real target remain in that target's split; changing a seed or
folder name does not make them independent held-out data.

The matched examples remove target-content differences between the real and
synthetic parts of an update. They do not by themselves make camera artifacts
identical or prove domain alignment; the new corruptions and held-out real
results test that hypothesis. The clean references are offline supervision,
not an additional model input or a browser decoding oracle.

## Training another run

Use the **already prepared 4×4-cell OBM5 datasets** for this recipe. If you need
fresh synthetic partners for those datasets, use the target-paired commands
above, writing into empty output directories. Current 2×2-cell Neural-QR datasets use the multires commands above; they do not
feed this independent U-tube recipe.

For a fresh U-tube experiment, train `U-tube-2x-attn` from scratch with eight
phase-paired slots and randomly selected 4–8 observations at `1e-4` for 32,000
updates. Use existing `real-train`, `target-synthetic-train`, `real-validation`
and their direction sidecar. Each training group must have at least two distinct
captures of every phase, although each draw uses only one or two. All examples
must be G64/16 colors with four permuted phases and the established 4×4-cell
input contract. Independently generated old synthetic phase bursts require
regeneration with the paired group recipe.

Use **batch 16 × accumulation 2 = effective batch 32**. Batch 8 × 4 retains that
effective batch if activation memory is limiting. The new output directory is
`U-tube-2x-attn-run`. This directory must be new. Cross-profile initialization
is rejected; a continuation of the current phase-grouped model may use its
validated `--initialize` checkpoint and an explicit learning rate. The current
successful run does not need retraining merely to export it for the browser.

```sh
python experiments/neural-corrector/train.py \
  --train local-data/real-train local-data/target-synthetic-train \
  --validation local-data/real-validation \
  --model U-tube-2x-attn --frames 8 \
  --session-groups local-data/session-groups.json \
  --paired-targets --real-fraction .5 \
  --batch-size 16 --accumulate 2 \
  --real-noise-std .008 --real-tint-stops .06 --real-exposure-stops .08 \
  --phase-flip-probability .25 \
  --lr .0001 --steps 32000 --eval-every 1000 --validation-samples 0 \
  --device cuda --out checkpoints/neural-corrector/U-tube-2x-attn-run
```

Each input uses fixed slots **P0a, P0b, P1a, P1b, P2a, P2b, P3a, P3b**.
K is uniform over 4/5/6/7/8. Every phase contributes one capture; K−4 randomly
selected phases contribute a second, and placement within each pair is random.
The remaining slots contain zero RGB and zero presence indicators. Real and
synthetic target partners receive the same K; members never cross physical
sessions, logical frames or independent synthetic phase groups. Targets are
canonical phase-zero data symbols, with unchanged physical reference labels.
Real photometric augmentation occurs before padding and never affects presence.

Two training-only augmentations apply to both real and synthetic groups:

- **Exact phase permutations**, enabled by default: choose d from `[0,15,7,8]`,
  reorder whole phase pairs and their presence indicators, then XOR only data
  labels by d. For example, d=15 swaps phases 0↔1 and 2↔3. RGB values are not
  recolored. `--no-phase-permutations` disables this augmentation.
- **Joint spatial flips:** independently flip horizontally/vertically with
  `--phase-flip-probability .25` each. Apply the same flip to all RGB slots,
  labels and masks; zero disables both. This provides classification examples,
  not new canonical wire-format messages. Neither augmentation is applied to
  validation or stored files. Recovery on transformed predictions would first
  have to reverse the transformation.

With effective batch 32 and two mapped directions, each update contains eight
real PC→phone examples, eight real phone→PC examples and sixteen matched
synthetic partners. Extra sessions add diversity without changing this balance.
Synthetic `--frames 12` means captures per phase burst; training `--frames 8`
means capacity, with 4–8 actual captures per input. Four-frame inference requires
**one from each phase**, not the first four camera exposures regardless of phase.

The run writes the lean files described under
[metrics and report files](#metrics-and-report-files). The evaluation table
contains a K dimension; unique-candidate counts describe shared logical groups,
and observation-case counts describe their repeated evaluations across K. Selection weights
K equally and, with the direction sidecar, real directions equally; CE breaks
selection ties. It never selects whichever K happens to look best.

History retains canonical training/evaluation rows and a training K histogram.
The table dimensions support source, group and K summaries without nested copies.
Per-session or per-candidate diagnostics require the standalone detailed-report
option. Inspect K4 and K8 separately alongside the per-direction summaries.

### Evaluate all five observation counts

```sh
python experiments/neural-corrector/evaluate.py \
  --dataset local-data/real-validation --split validation \
  --checkpoint checkpoints/neural-corrector/U-tube-2x-attn-run/best.pt \
  --session-groups local-data/session-groups.json \
  --max-samples 0 --device cuda \
  --out local-results/neural-corrector/U-tube-2x-attn-validation.json
```

The evaluator shuffles each phase pool once with fixed seed 7, makes disjoint
pairs, and joins pairs from the four phases of the same logical matrix. It uses
one member from each pair at K=4, then adds second members in a fixed shuffled
phase order for K=5/6/7/8. Every K therefore tests the same candidate targets
with nested evidence. Classical scores reverse each member's own phase mapping;
neural predictions are already canonical. Both receive the same actual captures,
and padding never counts as evidence. Remainders and incomplete groups are
reported, never duplicated into a candidate.

For six complete logical groups with 32 captures in each of four phases, there
are **96 candidates per K**. The five per-count evaluations reuse candidates;
their sum is not an independent matrix count. Compare per-direction/per-count
rates and equal observation budgets instead of old single-phase success totals.
Fixed-frame U-tube/U-tube-2x evaluation retains its existing grouping.

For this fresh run, step-zero `baseline-validation.json` is diagnostic random
weights, with no parent checkpoint. Share `validation.json`, `history.json` and
the standalone validation report. Keep untouched test sessions for the selected
model/settings. The completed run has exceeded the phone→PC target on recorded
validation; assess generalization on new sessions and confirm zero wrong accepted
payloads. Check the fixed-profile 4-color control separately before live integration.
